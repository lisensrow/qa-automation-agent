# Назначение, возможности и готовность

UQA — QA-агент с LLM-планированием, браузерным исполнением и проверкой результатов по доказательствам. Основной текущий приоритет — регресс плагинов агента U-Connect по ОС, сначала отдельными тест-кейсами без Jira. Стратегическая цель — общая проверяемая память для QA, документации, разработки и техподдержки.

## Возможности

- Принимает задачу и expected, сохраняет Job и test cases на диске.
- Работает с поддержанными семантическими UI-контролами: таблицы, формы, вкладки, фильтры и ограниченные многошаговые сценарии.
- Сохраняет observations/evidence и различает PASS/FAIL/BLOCKED в пределах реализованных контрактов; отсутствие доказательства не подменяется уверенностью модели.
- Читает выбранные CI/agent/plugin metadata и телеметрию из наблюдённого UI/API в пределах поддержанных инструментов.
- Имеет Action Policy для чтения, взаимодействия, изменений и destructive-действий.
- Ведёт resource ledger, durable intent journal и отдельные механизмы восстановления/проверки cleanup.
- Использует официальный документный FTS и ограниченную version-aware продуктовую память.
- Первый этап новой памяти добавляет типизированные candidate записи, проверку происхождения и дедупликацию без замены старой базы.

## Что действительно подтверждено

Новый явный профиль условий коллекций прошёл обычный Core-прогон локальной модели для Windows и Ubuntu: навигация без операторской подготовки, три строки и независимая сверка шести ячеек несохранённой формы. Это не полное создание/сохранение, вложенные условия или выполнение любого промпта. Финальные241 smoke — технические проверки, не241 реальный сценарий UC.

Реальные узкие сценарии включают чтение карточки/вкладки Agent Windows и Ubuntu, prepared поиск с заполнением/очисткой и просмотр/закрытие формы. Десять новых коллекций созданы и проверены по составам при операторском сопровождении. Это не доказательство автономности любого create/update/delete workflow.

## Что не обещаем

Пока не приняты: полностью автономный регресс всех плагинов/ОС, произвольный frontend, установка/доставка всех плагинов и обновление ядра силами UQA, Jira/Zephyr integration, автоматическая публикация любых знаний и shared memory API других агентов. Абсолютное отсутствие ошибок не гарантируется. Read-only PASS не подтверждает исполнение команды агента или состояние оборудования вне выбранного критерия.

В новой памяти все записи первого этапа остаются candidate или conflict. Проверка источника не означает проверку смысла вывода. Нет обещания «агент обучен весами»; память подаёт контекст для следующего прогона.
