# Наблюдения, доказательства и verdict

Observation — структурированный факт runtime. Evidence — связанный источник для проверки, содержащий происхождение, время и признаки пригодности. Expected задаётся доверенным требованием/контрактом, а не выводится из того же actual, который проверяется.

- PASS: необходимые поддержанные критерии доказаны.
- FAIL: есть достаточное доказательство нарушения заданного критерия.
- BLOCKED: нет prerequisite/поддержанного критерия/пригодных данных, либо операция неопределённа.

HTTP ACK, нажатие Save, завершение workflow, наличие результата задачи и модельная уверенность не равны бизнес-PASS. Свежесть телеметрии, версия плагина и actual command output — разные проверки.

## Целостность и бюджеты

Evidence JSON: до 262144 UTF-8 байт. Native network response body: до 65536 символов; request body: до 8000. Превышение явно помечается metadata-заглушкой; усечённый JSON не используется как полное доказательство или для reconciliation. Redaction чувствительных полей/заголовков сохраняется.

Новый source validator v1 допускает runtime источник только как конкретный native network GET: eligible evidence, exact case/ID, связанное observation, структурированный response без truncation и совместимая известная identity. Это проверка источника кандидата, не полноценный oracle его произвольного утверждения.

Известный пример: None-подобный текст в аппаратной таблице UC не считается числом; правильный состав коллекции не подтверждает отображение метрики.
