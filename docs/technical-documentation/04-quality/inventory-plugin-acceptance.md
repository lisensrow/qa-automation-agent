Закреплены девять профилей: driveDeviceAudit1.3.5, gpuDeviceAudit1.3.2, softAudit1.3.8, smbiosAudit1.3.8, networkDeviceAudit1.5.1, serviceAudit1.3.2, displayDeviceAudit1.3.2, processMonitoring1.3.2, baseSystemMonitoring1.3.3. ## Разделение ответственности

Модель выбирает предметное действие. Framework ограничивает доступные фазы по фактам; действия «обновить inventory» и «запустить аудит» не принимают переопределения цели/версии. Trusted compiler подставляет эти значения из immutable locked case и вызывает тот же защищённый Core. Это детерминированная помощь, не свободное планирование и не доказательство знания моделью произвольного API.

Доставка, загрузка и бизнес-корректность проверяются отдельно. Execution verified означает точную отправленную задачу с собственным успешным результатом, а не PASS всего тест-кейса. Защита результата требует agent/task/CI identity, session/origin и свежести. В модель и общую память не передаются полные списки процессов, пользователей и сетевых адресов: используются количества, проверяемые поля и hash.

Продолжение после частичного выполнения допускается только по ссылке на ранее verified delivery, с проверкой exact scope, journal fingerprints, первичного evidence и отсутствия неопределённых операций. Новый case исключает delivery-stage: повторная установка не отправляется. Старый failed case сохраняется, его expected и результаты не переписываются. Подготовка такого continuation-контракта оператором явно отмечается.
