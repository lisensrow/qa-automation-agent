# Приёмка модельного workflow osAudit

Проверено 15 октября2026 на Windows10Pro22H2/build19045.6456 и AstraLinux1.8/build1.8.1.6, core1.3.27 и osAudit1.3.4. Версии ОС взяты из inventory/результатов, не независимой физической инспекции.

Локальная qwen3:14b через штатный UQA Core выполнила на каждой цели: поиск памяти → текущую проверку готовности → обновление устаревшего списка плагинов через pluginAudit → чтение своей новой задачи и свежего loaded inventory → новую osAudit → чтение её свежего результата → канонический expected/actual отчёт. Обе новые операции каждого Job подтверждены по первичным ответам. Отправка команды и успешный HTTP-ответ сами по себе не считались результатом.

## Кто что сделал

- Оператор заранее закрепил разрешённые цели, исторический baseline и профиль; ранее обновил ядра и доставил плагин. Это не засчитано самостоятельными действиями модели.
- Супервизор подтвердил по две точные WRITE-операции каждого Job на основании разрешения пользователя; прежняя policy не заменялась.
- Framework ограничивал доступные фазы по native фактам, проверял журнал и строил отчёт независимо от свободного ответа модели. Это явно учтённая детерминированная помощь.
- Модель выбирала и вызывала инструменты. Во время прогонов оператор не выполнял действий на целях и не давал ей подсказок. Windows получила один отказ при преждевременном osAudit и сама выбрала pluginAudit; Astra сразу выбрала refresh.

## Что означает результат

Цепочка исполнения завершена на обеих ОС; бизнес-вердикт обоих cases — BLOCKED. Старый baseline ожидал иные OS name/version: Windows name теперь Windows10Pro (фактически «Windows 10 Pro»), version19045.6456; Astra name теперь «Astra Linux». Исходные expected не переписаны. Это наблюдаемая несовместимость прежнего примера, не подтверждённый разработчиком баг/фикс. Реальные expected/actual таблицы сохранены UQA внутри соответствующих Jobs. Jira/Zephyr не изменялся.

Full311:250/250 технических smoke PASS. Это не250бизнес-проверок и не полный регресс40кейсов. Самостоятельная доставка/обновление локальной моделью, свободные задания и остальные плагины ещё не приняты. Уже актуальные ядра/плагины не переустанавливались ради повторной демонстрации. Старые неопределённые journal операции не освобождались и не переотправлялись.

Неудачные попытки до этой приёмки сохранены: clock mismatch, generic UI loop, ошибочный свободный отчёт и выбор osAudit при stale inventory. Знания хранятся с источниками, версиями и историей; reviewed candidate не превращается автоматически в глобальную verified истину продукта.
