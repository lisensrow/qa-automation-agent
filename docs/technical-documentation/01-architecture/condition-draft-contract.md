## Назначение

Отделить понимание человеческого задания от управления конкретным интерфейсом. Модель выбирает логические условия; проверяемый компилятор строит низкоуровневые действия по доверенному профилю. Память помогает выбрать применимый профиль, но не заменяет текущую проверку UI, разрешение или oracle.

## Что реализовано

Универсальный condition_plan проверяет закрытый профиль caller: поля, видимые labels, родители дерева, колонки, допустимые операторы и тип заполнения. Hash закрепляет профиль. Модель не может передать URL, session, endpoint, инструмент, произвольный selector или изменить профиль. Typed union в схеме связывает конкретное поле только с его допустимыми операторами; независимый валидатор повторяет эту проверку.

Expected задаёт caller до generation; это не предложение модели и не actual из UI. План сравнивается с expected, проверяются логика, неизвестные поля/операторы, дубликаты и размеры. Порядок строк одного плоского логического объединения нормализуется. Смена значения или профиля отклоняется, а не исправляется по actual.

После проверки компилятор возвращает только ограниченные UI-шаги. В них нет session/URL: эти привязки должен добавить runtime из свежего native состояния. Все execution/current-runtime/saved-filter/membership/business-PASS flags остаются false. Чистая компиляция не исполняет действий и не освобождает journal.

browser_add_tree_row_semantic выполняет один составной WRITE: точные родители → draggable leaf → единственный logical drop target → exact row/column controls. Он не сохраняет форму. Неоднозначность, существующая строка, смена session/URL и частичная ошибка запрещают автоматический повтор. Прежние policy и compatibility checks остаются обязательными.

## Границы текущего профиля

Обновлённый профиль v2 различает лист дерева и результирующую строку: OS name в дереве и Endpoint.OS name в таблице. Optional row_label задаёт проверяемый caller profile, а не модель. Поиск обоих имён точный; подпись UI нельзя считать backend key. Mapping имеет отдельный reviewed source hash, весь профиль закреплён до модели. При несовпадении интерфейса выполнение останавливается; fuzzy matching и автоматический повтор drag не добавлены.

В normal prepared Windows-прогоне v263 новый mapping и финальные шесть ячеек приняты штатным verifier. Короткое Ubuntu-задание остановилось ещё до condition writes: Wildcard Ubuntu вместо ожидаемого *Ubuntu*. Это ограничение логического извлечения, не доказательство отсутствующего поля. Старые неудачи остаются BLOCKED; полный Save/AST/member workflow не принят.

Отдельное задание v266 с явным contains/Wildcard/*Ubuntu* прошло тот же normal prepared entry без изменения production кода или oracle. Это подтверждает исполнение профиля для данного шаблона, а не исправление неуспешного короткого запроса. Technical final268241/241 PASS не равен241 сценарию UC.

Поддерживается плоская группа AND либо OR, заданная профилем, с уникальными полями. Наличие такого плана не доказывает, что соответствующая группа реально создана в UI. Вложенные группы, несколько условий одного поля, диапазоны, отрицания, преобразование единиц и неизвестные метрики не реализованы этим компилятором. Они должны получить отдельные типизированные контракты; нельзя молча упрощать их до одного сравнения.

Есть явный production requirement bounded_condition_draft с отдельным reviewed UC-профилем: плоский AND, Archived/CI class/OS name и ограниченные операторы. Требуются caller expected, source/profile/preparation pins, один planned criterion и пустые ресурсы/операции. Обычные STEP/AUTO и policy сохраняются. Свободное ручное задание не маршрутизируется в этот профиль автоматически; вне контракта model tool-choice может ошибаться.

Runtime сам открывает entry настроенного стенда, проверяет совместимость, переходит в новый редактор и Conditions, фиксирует свежие session/URL, извлекает reviewed знания и получает tool-free логический план. После независимой компиляции каждое действие проходит прежнюю policy. Durable once-only state записывается до действий; partial/uncertain не запускает fallback ReAct или повтор мутации. Никаких Save или автоматической смены oracle.

Новый зарегистрированный OBSERVE-инструмент читает точные значения/операторы ячеек, но наружу передаёт только hashes и длины. Обычный frontend verifier сверяет caller expected, полный уникальный набор, session/URL и отсутствие последующего WRITE. Ошибка значения — FAIL; неполное, неоднозначное, непригодное или устаревшее наблюдение — BLOCKED. Модельный boolean не принимается за доказательство.

Это узкий UI-phase PASS; saved AST, семантика всей группы, состав и полное создание не принимались. Первый prepared-job-entry252 затем остановился до WRITE на недоступной авторизации стенда; cert-login503 подтверждён отдельной диагностикой. Auth recovery использует только существующее предложение Core и прежний opt-in, не включает reuse credentials самостоятельно. Технический финальный набор253:241 smoke PASS. Старые BLOCKED сохранены.

Это устраняет ограничение «только промежуточные receipts» в данном узком прогоне, но не подменяет ещё отсутствующий normal runtime или saved/member oracle. ## Контракт runtime и следующие границы

1. Создать новый owned draft только по явно поддержанному persistent requirement. Закрепить stand, источник/profile hash, expected и scope до обращения к модели.
2. Получить логический план без инструментов; сохранить предложение до валидации, включая отклонённые варианты и фиксированный reason code.
3. Проверить и скомпилировать план. При несовпадении ничего не конфигурировать и не менять oracle.
4. Связать новый редактор с единственной свежей native session/URL и текущими контролами. Исторический рецепт не является доказательством текущей совместимости.
5. Выполнить каждый ограниченный WRITE через прежнюю policy. Partial/uncertain не переотправлять; записать точное достигнутое состояние.
6. Отдельно заново прочитать все значения и операторы после завершения настройки. Принимать фазу только по заранее объявленным критериям; четыре успешных промежуточных receipt не заменяют финальный readback шести ячеек.
7. Сохранение принимать отдельным immutable journal stage с независимым чтением saved AST и состава. Настроенный несохранённый UI не равен созданной коллекции.

## Переиспользование

Тот же принцип применим к условиям политик, но требует собственного профиля, явного inactive state и точной области применения. Для процедур нужен другой тип плана: блоки, связи, параметры и переменные, затем saved graph и отдельный execution oracle. Нельзя применять плоский condition compiler к произвольному графу или считать успешную структуру успешной командой на КЕ.
