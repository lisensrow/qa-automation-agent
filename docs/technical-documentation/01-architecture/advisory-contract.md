# Справочный ответ, предложение и исполнение

## Статус и обнаруженное ограничение

v214 реализует отдельный knowledge-only MVP. Расширения ниже остаются планом. Native диагностика v210 показала две разные проблемы: правильный источник найден, но пересказ неточен; затем Core потребовал тестовый JSON от задачи-объяснения. Извлечение, применение источника и завершение задачи проверяются отдельно; уменьшение контекста само по себе не делает ответ достоверным.

## Реализованный MVP

Явная команда `/advice STAND QUESTION` создаёт новый Job типа advisory до retrieval/model call. Это не автоматическое распознавание свободного текста и не новая ветка STEP/AUTO. Contract фиксирует stand, request hash, единственный knowledge_search и запреты model tools/business verdict. У такого Job нет cases/planned checks/resources. Обычный run_turn его отвергает; dispatcher дополнительно блокирует все другие инструменты, включая OBSERVE. Advisory marker сохраняет запрет при простой смене job_type. После ответа даже knowledge_search для этого Job больше не разрешён. Новое исполнение предложения требует отдельного обычного Job и прежней policy/journal.

До3запросов/4фрагментов/18000символов. MVP использует только существующую curated Markdown-папку UQA-experience: проверяются путь внутри configured root, размер, повторное формирование точного chunk, heading/number/content и hash исходного файла. После model call источники проверяются вновь. Docx/pdf/API источники пока не подключены именно к этому режиму; прежний общий knowledge_search не меняется. Curated root — доверенная операторская конфигурация, не multi-tenant RBAC. Нет нового индекса, миграции canonical memory или promotion.

Source path должен быть каноническим внутри именно UQA-experience, а не просто где-либо внутри общего knowledge root: parent escape, alias path и backslash ambiguity отвергаются. Некорректный stand отвергается до создания Job; отменённый/изменённый Job не перезаписывается результатом generation. Эти отказы не снимают старые journal barriers.

Модель получает tools=[] и bounded JSON response schema с допустимыми source IDs. Код повторно проверяет answer/citations/limitations; tool calls, test JSON, неизвестные citations и unbound ev/obs ссылки отклоняются. Схема допускается только с пустым списком инструментов, прежние вызовы LLM без response_schema не меняются. Проверка ссылок не доказывает точность prose: factual_accuracy_verified/current_runtime_verified/evidence_for_pass/execution_authorized всегда false. Неизвестная версия не становится latest; текущий UI/API режим не обследует.

Ответ хранится в Job.advisory отдельно от test result. advisory.state=answered означает структурный справочный ответ, unavailable — отказ/недостаток источника. Базовый Job.status=blocked: существующий словарь не содержит информационного завершения, QA verdict отсутствует. Ошибка хранится безопасным кодом/типом, model receipt — hash/размер/признак tool call, без rejected raw prose и tool arguments. Resume/перевод advisory Job в исполнительный не поддержан.

Реальный CLI pilot с автоматически извлечённым опытом колонок назвал endpoint.os_name, объяснил отличие API/layout/map и отсутствие выполненного исправления. Это один справочный сценарий, не полная factual/admin приёмка. Первый ответ был rejected/unavailable с ValueError; точная причина не сохранена и задним числом не угадывается. Второй после добавления response schema принят структурно; safety validation не ослаблялась. Полный контракт ниже реализован не целиком: остаются расширение approved source adapters, безопасное намерение для свободного текста и дальнейшая проверка точности.

## Три результата

| Намерение пользователя | Допустимый результат | Что он не означает |
|---|---|---|
| Объяснить известную логику, предложить автоматизацию | Справочный ответ с источниками, ограничениями и неизвестными | Выполнение, готовность конфигурации или PASS |
| Проверить поведение | Проверки по locked expected и пригодным текущим evidence | Свободный пересказ вместо oracle |
| Создать или применить решение | Отдельное разрешённое исполнение через policy, scope и журнал | Разрешение из текста предложения |

Намерение не выбирает сама модель. Доверенный входной слой должен сохранять явный тип задачи. Для неоднозначного смешанного запроса безопасен отказ от исполнения до уточнения, а не превращение любого слова «как» в исключение из проверки. Уже запущенный тест с planned checks нельзя задним числом объявить справочным, чтобы обойти BLOCKED.

## Полный контракт и оставшиеся расширения

1. Справочный Job получает отдельный immutable contract до первого model turn. Не допускаются тестовые planned checks, mutation workflow/stage или присоединение операций к такому контракту. Неизвестный/противоречивый режим отклоняется; существующие Job сохраняют прежнее поведение.
2. Каталог справочных инструментов ограничен точным allowlist чтения знаний и зарегистрированных схем. Класса OBSERVE самого по себе недостаточно для разрешения любого SSH/API чтения. Проверка allowlist выполняется также при dispatch: скрытие инструмента от модели не является защитой. Даже общее лабораторное разрешение не превращает предложение в запрос выполнить его.
3. Для текущего обследования UI нужен отдельно явно разрешённый read-only contract. Исторический источник не становится текущим runtime evidence. Предлагаемый endpoint/payload проверяется по установленной схеме, а не по догадке; неизвестные enum/версии остаются неизвестными.
4. Справочный результат хранится отдельно от тестового verdict, с business_verdict отсутствующим и evidence_for_pass=false. Даже если модель прислала UQA_CHECKS_JSON, он не записывается как пройденный тест и не меняет статус существующего case. Конкретный формат хранения требует отдельной реализации и миграционного теста, не придумывается по факту ответа.
5. Ссылки сверяются с фактически извлечёнными approved sources и разрешённой историей. Выдуманный observation ID, чужой case или неподтверждённая версия не принимаются за основание. Корректная ссылка не гарантирует корректный пересказ: противоречия и неизвестная применимость показываются явно, автоматического verified promotion нет.
6. Исполнение предложенной процедуры требует нового явного запроса и отдельного execution Job с актуальными scope, policy, locked oracle и журналом. Справочный Job не повышается до исполнительного. Предыдущий свободный текст модели не является binding.

## Минимальная приёмка

Проверить: обычное объяснение без test JSON; обычный тест по-прежнему требует supported checks; попытку сменить режим после начала; смешанную задачу; модельный вызов скрытого WRITE/DESTRUCTIVE/неизвестного инструмента; OBSERVE вне allowlist; выдуманные citations/observations; исторический source вместо текущего proof; предложение выполнить без пользовательского согласия; повторное использование чужого scope; отсутствие записи PASS и product-memory promotion из справочного текста. Затем нужен новый native прогон локальной модели без операторских chunks. Содержательная точность ответа измеряется отдельно от правильности маршрутизации.
