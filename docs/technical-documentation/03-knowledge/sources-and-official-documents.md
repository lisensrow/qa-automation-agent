# Источники и официальная документация

Официальные руководства U-Connect уже находятся в документном индексе, включая пользовательское/административное руководство и API материалы. Они остаются первичными источниками, не заменяются описанием, написанным LLM. Документация самой UQA — архитектура, CHANGELOG, этот пакет и design proposals — относится к продукту UQA/проектным решениям, не к нормативному поведению UC.

## Правила официального источника

Trusted registry указывает source ID, relative path внутри разрешённого root, SHA-256, publisher, revision и явно одобренную applicability. Сам JSON candidate не может назначить документ official. Имя файла или количество повторных ссылок не доказывает авторитет.

Validator сверяет реальные байты с registry и ref hash, document_revision и declared applicability. Путь вне root, escaping symlink, незарегистрированный файл и source over budget отвергаются. Читаемые форматы: docx/pdf/xlsx/md/txt, не более 32 MiB в source adapter. В этом этапе validator не парсит каждый формат заново и не доказывает, что произвольный claim следует из документа.

Developer confirmation — отдельный тип документа с одобренной атрибуцией developer role в trusted registry, не ярлык из входного JSON. Он допускает candidate заявления о признанном issue/fix version, но не становится официальным пользовательским руководством и не доказывает runtime устранение бага.

Дата руководства не равна server/frontend release. Неизвестная применимость сохраняется unknown. Чтобы связать документ с конкретным релизом, нужна явная проверенная декларация registry. Contract/declared_spec требует approved official source; curated operator recipe не становится официальной спецификацией.

## Изменения и история

Новая редакция получает новый hash/revision и source manifest. Старые manifests, event/support references и legacy confirmations не перезаписываются. Новое изложение ожидаемого поведения сохраняется отдельно от observed actual; расхождение фиксируется как конфликт/ограничение.

В первом этапе новая таблица сохраняет manifests, а не архивные копии всех файлов. Автоматический watcher, downloader, byte-snapshot importer и diff extractor руководств ещё не реализованы. Уже имеющиеся руководства не переименовываются/удаляются. При новой поставке сохранить старый файл отдельной редакцией до согласованного импорта; нельзя заменять байты и продолжать ссылаться на старый hash.

Концепции продукта, термины и API должны ссылаться на официальную редакцию. Продуктовые выводы из теста и гипотезы причины дефекта — другие уровни знаний. Runtime source также должен существовать в exact Job/case, иметь eligible native receipt и linked observations; чужой/усечённый receipt не принимается.

Частные конфиги, secrets, session cookies, сырые task output и raw logs не импортируются в общий документный корпус. Pattern checks не заменяют review источника и права доступа.
