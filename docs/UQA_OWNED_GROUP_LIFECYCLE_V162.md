## Что исправлено универсально

- Подпись столбца Name больше не связывается с чекбоксом выбора строки; одинаковые по HTML реальные поля не объединяются в одно.
- Явный контейнер-владелец соблюдается в fallback поиска кнопок по иконке и тексту. Защита настоящей неоднозначности и прежний осмотренный exact fallback сохранены.
- Проверка наблюдённых идентификаторов понимает JSON-текст тела ответа, с ограничением размера/глубины; не извлекает ID из произвольного текста или request body.
- STEP/AUTO, v069 policy и требование подтверждать реальные изменения не менялись. UC-specific ветвления в Core не добавлены.
- Следующий этап v164: metadata-driven cleanup передаёт известный ID реестра; DELETE/archive блокируются до мутации при другом ID с тем же именем. Проверено на изолированной странице с искусственным fetch, не на новом объекте стенда. Legacy ресурсы без ID сохраняют прежнее поведение и не считаются защищёнными этим сравнением.

## Границы результата и следующие этапы

После v164 полный runner: 204/204 PASS; py_compile PASS. Сохранены smoke настоящей field ambiguity, exact role fallback, старого REST cleanup, модели/policy, ledger recovery и новых ID-проверок. Регрессионные ошибки, найденные промежуточными прогонами, исправлены до этого итогового результата.

Это реальный, но управляемый интеграционный тест. Нельзя назвать его полностью автономным модельным PASS: оператор подтвердил разрешённые действия, диагностический скрипт восстановил ID, выполнил rename и задал metadata-driven cleanup contract. Доказательства контроля хранятся отдельно от автоматического verdict. Старые неудачные Jobs не удалены и не переписаны в PASS.

Дальше: автономный prepared lifecycle-контракт и вычислимые проверки по runtime evidence; подтверждение ID binding новым разрешённым live прогоном и защита повторного выполнения; отдельное тестирование восстановления после таймаутов. Для новых live-ресурсов потребуется новая узкая авторизация — разрешение на одну группу уже использовано. Затем пилот на реальных задачах отдела и обратная связь.
