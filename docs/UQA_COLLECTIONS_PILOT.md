## Что проверено и что не закрыто

All содержит четыре Endpoint Windows, Ubuntu, Astra и RED OS. Общие условия — Archived = No и CI class = Endpoint. OS условия используют текущие os_name; Linux — объединение трёх наблюдённых дистрибутивов, не распознавание любой будущей ОС.
RAM inventory: value_count(size)>=1 по ram; threshold: SUM(size)>=2147483648 байт. У каждой машины один наблюдённый RAM CI размером 2 GiB.
CPU inventory: value_count(core_count)>=1 по cpu; threshold: MAX(core_count)>=4. У каждой машины четыре CPU CI с core_count=4; это НЕ доказательство 16 физических ядер. Аппаратные фильтры не измеряют текущую нагрузку.

Отдельное ограничение отображения: child_size/child_core_count — префиксы условий, не столбцов renderer. Только новые четыре layouts приведены к ram.size/cpu.core_count по прочитанному backend контракту. Native таблицы всё равно возвращают None-подобный текст, хотя отдельный inventory содержит числа. Наличие столбца и HTTP200 не считается успешным показом метрики. Ошибка первоначального слабого критерия «не null» в операторском диагностическом script исправлена: строка "None" не является числовым доказательством; актуальная ledger metadata metric_values_verified=false. История не удалена. Причина UC окончательно не установлена, его код не патчился.

Не закрыты: отображение аппаратных значений, условия текущей нагрузки, Auto-пересчёт и автономное воспроизведение рецепта LLM. Итог не называется полной бизнес-приёмкой всех критериев. Коллекции оставлены пользователю.

## Воспроизводимая последовательность формы

1. Проверить отсутствие нового имени в полном списке.
2. Назвать новую коллекцию, выбрать условия и Manual для явного пересчёта.
3. Посетить Composition, Conditions, Table fields, Settings и Policies; политики не назначать без разрешения. Table fields инициализирует layout и в наблюдённой форме снимает disabled Save.
4. Проверить имя, условия и active Save. Действовать через штатную policy, сохранить intent до отправки.
5. После сохранения проверить ID/настройки native GET, зарегистрировать collection/filter и зависимость в ledger.
6. Отдельно пересчитать новую коллекцию; ACK 202 не равен успеху. При timeout не повторять POST, сначала читать состояние.
7. Сравнить точные CI ID полного состава и таблицы с независимым expected. Для столбцов проверять значения, не только ключи/HTTP200.

Подробный очищенный рецепт, источники и ограничения — UQA_COLLECTIONS_KNOWLEDGE.md, индексируется существующим knowledge_search. Память не является разрешением нового создания или evidence для PASS.

## История блокеров и разрешение

Первый disabled Save до Table fields возвратился до клика; старая версия журнала ошибочно оставила uncertain. Native observation/screenshot и backup adapter source дали основание узкому auditable review, история сохранена. Затем web-сессия истекла (419/428/login); новое открытие и штатная авторизация восстановили доступ.
Исходный Auto не позволял ручной POST пересчёта: backend отвергает HTTP400 до command_bus.dispatch. Только новая All переведена в Manual через обычную policy и проверена native GET. Вывод «любой 400 безопасно повторять» запрещён.
Пересчёт затем получил timeout 30 секунд из-за RabbitMQ disk alarm: 4.6 GiB свободно при пороге 5000000000 байт, 13 blocked/10 blocking соединений. XHR response list не доказывал отсутствие отправки; dialogs=[] не подтвердил гипотезу скрытого confirm.
