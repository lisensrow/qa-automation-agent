# Проверка создания коллекций UQA

## Область разрешения

Пользователь разрешил создать около десяти новых коллекций для четырёх машин lab. Имена начинаются с uqa-test-collections-. Существующие коллекции, агенты и другие объекты не менять; политики не применять; новые коллекции оставить для просмотра. STEP/AUTO и v069 подтверждения сохранены.

## Основания для условий

Источник — «UC Руководство пользователя от 06.07.2026», раздел коллекций, и текущие UI/network наблюдения. Коллекция вычисляется как автоматический состав плюс ручные включения минус исключения. Для состава машин нужны Archived = No и CI class = Endpoint. Условия вычисляются по CMDB, не по текущему составу коллекции. При clear_on_update=true состав пересчитывается; false означает накопление. RAM Sum агрегирует модули одной машины. Отсутствующие значения не следует выдавать за ноль.

Фильтры RAM/CPU по аппаратным характеристикам не равнозначны фильтрам текущей нагрузки. Единицы, агрегаты и доступность нагрузки необходимо проверить по фактическим данным до выбора порогов.

## Последовательность формы

1. Убедиться, что новое имя отсутствует в полном исходном списке коллекций.
2. Открыть новую форму, назвать коллекцию и установить требуемый режим пересчёта.
3. Задать условия, проверяя каждый контрол по строке и столбцу.
4. Посетить Composition, Conditions, Table fields, Settings, Policies. Не запускать и не назначать политику. Проверить, что Table fields действительно инициализированы.
5. Снова проверить точное имя, условия и доступность Save. Не пытаться «дожать» disabled-кнопку.
6. Сохранить через существующую policy и durable журнал с исходным oracle.
7. Прочитать свежий полный список, подтвердить уникальный ID нового объекта, затем прочитать его состав и сравнить точные ID машин с ожидаемыми.
8. Зафиксировать новый объект в resource ledger; оставить его активным для пользователя. Не объявлять PASS по клику или HTTP ACK.

## Фактический статус 14 октября 2026

Контролируемый операторский bridge работает через штатный Core и настоящие подтверждения, не через автономный LLM. Job 20261014-141458-054a6654, case tc-55cd1a6b. Наблюдены четыре online Endpoint: Windows, Ubuntu, Astra, RED OS. Существующая коллекция all не изменена.

Черновик 01 All имеет имя uqa-test-collections-01-All, Auto, clear_on_update=true, условия Archived Equal No и CI class Equal Endpoint. Все вкладки просмотрены; после Table fields Save стала активна. Сохранённых новых коллекций пока нет, состав ещё не принят.

Первый Save до открытия Table fields был отклонён браузером как element_disabled / not_executed до начала клика. Старая версия журнала записала op-3ef2e788f588468cb1f5e896cbc0c0c5 как uncertain. Запись сохранена, не подменена и не снята обходом через другой Job. Новая обработка нативного not_sent предотвращает такой барьер в будущих попытках, но автоматически не пересматривает исторические uncertain.

При последующем возврате в Settings истекла web-сессия: GET параметров групп вернул 419, /check-auth — 428, появилась форма Login/Password. Это отдельный инфраструктурный блокер, не ошибка условий и не доказательство создания. Повторный вход должен выполняться штатным secret-safe auth инструментом, без вывода сохранённых credentials.

## Проверки и оставшиеся ограничения

Изолированные Playwright fixtures проверяют адресацию таблиц/div-grid и настоящий отказ disabled-кнопки без клика. Журнал проверяет сохранение обеих попыток, неизменность tool/arguments/oracle, блокирование JSON-подделки и таймаута. Это технические проверки, не десять готовых коллекций и не обучение весов модели.

Установленный v172: py_compile PASS; общий runner 214/214 PASS. Дополненный профильный тест подтвердил повтор обычного подтверждения Core после not_sent и блокирование третьей попытки после отправленного клика. Ни fixture, ни профильный тест не подключались к UC и не выполняли destructive-действий.

Дальше: разрешить исторический барьер проверяемым, аудируемым способом; сохранить первую коллекцию и подтвердить четыре ID; затем выполнять оставшиеся варианты. Нужны фактические аппаратные данные и единицы RAM/CPU, native membership evidence, ledger регистрация и отдельный автономный пробный запуск. Известное ограничение старого evidence writer: текстовое обрезание длинного JSON может давать невалидный JSON; не использовать такой обрезок как подтверждение выполнения.
